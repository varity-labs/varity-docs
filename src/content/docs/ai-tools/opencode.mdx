OpenCode runs the Varity MCP server (`@varity-labs/mcp`) as a local stdio
server. Once it is added, ask OpenCode to check the cost of a deployment,
deploy a repository and report the live URL.

<Aside type="note">
These steps follow OpenCode's own documentation. Varity has not yet tested
them in OpenCode.
</Aside>

## Before you start

- **Node.js 22.11 or newer**, so OpenCode can start the server with `npx`.
- **A Varity account.** On the first deploy, the Varity server asks you to
  confirm in a browser tab to connect Varity. There is no key to copy. Never
  paste a key into the chat.
- **For CI or scripts only:** a deploy key from the Developer Portal under
  **Settings > Deploy keys**, exported as `VARITY_DEPLOY_KEY` in the shell that
  starts OpenCode:

  ```bash
  export VARITY_DEPLOY_KEY="<your deploy key>"
  ```

## Add the server

```bash
opencode mcp add varity -- npx -y @varity-labs/mcp@latest
opencode mcp list
```

OpenCode 1.x writes the server to your global config. OpenCode 2 writes it to
the project config; add `--global` there to use it in every project. A local
server inherits OpenCode's environment, so it reads a `VARITY_DEPLOY_KEY` you
exported.

## Or edit the config file

To configure the server by hand, add it to `opencode.json` in your project, or
to `~/.config/opencode/opencode.json` for every project. The
`{env:VARITY_DEPLOY_KEY}` value reads the key from your environment, so the key
itself never sits in the file. The `environment` entry is only for a deploy key
in CI or scripts; without it, the server connects through the browser sign-in.

<Tabs>
  <TabItem label="OpenCode 1.x">
    ```json
    {
      "$schema": "https://opencode.ai/config.json",
      "mcp": {
        "varity": {
          "type": "local",
          "command": ["npx", "-y", "@varity-labs/mcp@latest"],
          "enabled": true,
          "environment": {
            "VARITY_DEPLOY_KEY": "{env:VARITY_DEPLOY_KEY}"
          }
        }
      }
    }
    ```
  </TabItem>
  <TabItem label="OpenCode 2">
    OpenCode 2 places servers under `mcp.servers` and has no `enabled` field:

    ```json
    {
      "$schema": "https://opencode.ai/config.json",
      "mcp": {
        "servers": {
          "varity": {
            "type": "local",
            "command": ["npx", "-y", "@varity-labs/mcp@latest"],
            "environment": {
              "VARITY_DEPLOY_KEY": "{env:VARITY_DEPLOY_KEY}"
            }
          }
        }
      }
    }
    ```
  </TabItem>
</Tabs>

<Aside type="caution">
Never put a real key in a checked-in configuration file. Use
`{env:VARITY_DEPLOY_KEY}` as shown.
</Aside>

## Check the install

Ask OpenCode to "check my Varity environment". It runs `varity_doctor`, which
reports whether a deploy key is configured. Then ask it to "estimate the cost of
deploying this project to Varity" before you deploy.

The full tool list and client setup for other editors are on the
[MCP Server Reference](/ai-tools/mcp-server-spec/).
