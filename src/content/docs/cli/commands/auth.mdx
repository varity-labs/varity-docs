Log in to Varity from the CLI. `varitykit login` opens your browser: confirm there and the CLI saves a deploy key for this machine. There is no key to copy. Authentication is required for deploying apps and managing domains.

## Usage

```bash
# Top-level shortcut
varitykit login

# Or use the auth subcommand
varitykit auth login
```

Both commands do the same thing.

<Steps>

1. **Run the login command**

   ```bash
   varitykit login
   ```

   The CLI opens a browser tab. Sign in to the developer portal if asked, then confirm to connect the CLI. The CLI saves the deploy key Varity creates for this machine.

2. **Verify you are logged in**

   ```bash
   varitykit auth status
   ```

</Steps>

## Commands

### login

```bash
varitykit login            # sign in through the browser
varitykit login --device   # sign in with a code on another device
varitykit login --key <key>
```

- **Browser (default):** opens a browser tab to confirm.
- **`--device`:** for SSH sessions and machines without a browser. The CLI shows a link and a code: open the link in a browser on any device and confirm the code. A headless machine uses this automatically.
- **`--key <key>`:** for CI and agents. Create a deploy key in the developer portal under [Settings > Deploy keys](https://developer.store.varity.so/dashboard/settings?tab=api-keys&utm_source=docs&utm_medium=content&utm_campaign=docs-to-portal&utm_content=cli-auth-api-keys) and pass it here, or set it as `VARITY_DEPLOY_KEY`.

If you are already logged in, the CLI will show your current key (masked) and ask if you want to replace it.

### logout

Remove your saved credentials from this machine.

```bash
varitykit auth logout
```

This revokes the deploy key on Varity, so it stops working everywhere you use it, then removes it from this computer. A key you saved with `--key` is revoked too. You will need to run `varitykit login` again to deploy.

### status

Show your current login status.

```bash
varitykit auth status
```

Example output when logged in:

```
  Logged in (key: vk_...7f2a)
```

Example output when not logged in:

```
  Not logged in.
  Run 'varitykit login' to connect your developer account.
```

## Where Credentials Are Stored

Credentials are saved to `~/.varitykit/config.json` with restricted file permissions:

| Path | Permissions |
|------|-------------|
| `~/.varitykit/` | `700` (owner-only access) |
| `~/.varitykit/config.json` | `600` (owner-only read/write) |

The config file holds one credential:

| Key | Description |
|-----|-------------|
| `deploy_key` | Your developer portal deploy key |

## When Is Authentication Required?

| Command | Requires Login |
|---------|---------------|
| `varitykit app deploy` | Yes |
| `varitykit app list` | Yes |
| `varitykit migrate` | Yes |
| `varitykit doctor` | No |

## Troubleshooting

### "Not logged in" when deploying

Run `varitykit login` and confirm in the browser tab. In CI, pass a deploy key with `varitykit login --key <key>` or set `VARITY_DEPLOY_KEY`.

### "Invalid deploy key"

If you passed a key with `--key` or `VARITY_DEPLOY_KEY`, make sure you copied the full key from the developer portal Settings page. The key must be at least 10 characters long.

### Credentials not persisting

Check that the CLI has write access to your home directory:

```bash
ls -la ~/.varitykit/
```

If the directory does not exist, `varitykit login` will create it automatically.
