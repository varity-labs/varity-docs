When your code needs a database, Varity provisions one in the same deployment and injects the connection details. You don't create accounts, copy connection strings, or wire anything up. This page explains what you get and, importantly, what the durability boundary is in beta.

## What Gets Provisioned

Varity detects these from your dependencies and provisions them alongside your app:

<CardGrid>
  <Card title="Postgres" icon="seti:db">
    Relational database, with `pgvector` for embeddings. Injected as `DATABASE_URL`.
  </Card>
  <Card title="Redis" icon="seti:db">
    In-memory cache / store. Injected as `REDIS_URL`.
  </Card>
  <Card title="MongoDB" icon="seti:db">
    Document database. Injected as `MONGODB_URI`.
  </Card>
  <Card title="MySQL" icon="seti:db">
    Relational database. Injected as `MYSQL_URL`.
  </Card>
</CardGrid>

Varity also provisions an **S3-compatible object store** (`MINIO_URL`,
`MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`) when the current detection contract
matches. Detection and the full env-var list are covered in
[Auto-wired Services](/deploy/auto-wired-services/).

Your app reads these from its environment. No connection strings to manage:

```js
// Varity injects DATABASE_URL; just read it
const db = process.env.DATABASE_URL;
```

## Durability in Beta: Read This

<Aside type="caution" title="A redeploy resets attached databases">
Attached databases and object storage run inside your app's deployment. A redeploy, restart, environment-variable change, re-publish, or AI Gateway attach replaces that deployment, and its attached databases and object storage start empty. They are not a managed database product: there are no automated backups, no high availability, and no point-in-time recovery.
</Aside>

What this means in practice:

- **Good for:** demos, prototypes, and data you can recreate.
- **For data you need to keep:** use your own external database for now (see [Bring Your Own Database](#bring-your-own-database)). Your app deploys exactly the same way. It connects to your database instead of an attached one.

## Bring Your Own Database

To use an external database, set its connection string as an environment variable (for example `DATABASE_URL`) when you deploy, and Varity won't provision its own. See [Environment Variables](/deploy/env-variables/).
