The Varity AI Gateway is an OpenAI-compatible inference API. It speaks the same
chat-completions wire format as the OpenAI API, so every OpenAI SDK, framework
adapter, and agent runtime already knows how to talk to it. For chat,
streaming, tool calls, embeddings, image generation and editing, speech, and
transcription, the integration is a one-line base-URL swap.

```text
https://ai.varity.app/v1
```

`https://ai.varity.app` is the canonical AI Gateway host; the older
`varity.app/v1` alias is described on [Endpoints](/ai-gateway/endpoints/#host).

Chat completions are the core, and the same host serves OpenAI-compatible
[embeddings, image generation and editing, transcription, and
speech](/ai-gateway/compatibility/) on the models whose `capabilities` advertise
them.

## Fastest Path

Set two variables and send a request. This is the whole integration.

<Tabs>
  <TabItem label="curl">

    ```bash
    curl https://ai.varity.app/v1/chat/completions \
      -H "Authorization: Bearer $VARITY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "glm-5-2",
        "messages": [
          { "role": "user", "content": "Say hello in one sentence." }
        ]
      }'
    ```

  </TabItem>
  <TabItem label="Python">

    ```python
    # pip install openai
    import os
    from openai import OpenAI

    client = OpenAI(
        base_url="https://ai.varity.app/v1",
        api_key=os.environ["VARITY_API_KEY"],
    )

    response = client.chat.completions.create(
        model="glm-5-2",
        messages=[{"role": "user", "content": "Say hello in one sentence."}],
    )

    print(response.choices[0].message.content)
    ```

  </TabItem>
  <TabItem label="Node">

    ```javascript
    // npm install openai
    import OpenAI from "openai";

    const client = new OpenAI({
      baseURL: "https://ai.varity.app/v1",
      apiKey: process.env.VARITY_API_KEY,
    });

    const response = await client.chat.completions.create({
      model: "glm-5-2",
      messages: [{ role: "user", content: "Say hello in one sentence." }],
    });

    console.log(response.choices[0].message.content);
    ```

  </TabItem>
</Tabs>

`base_url` / `baseURL` is the only line that differs from an OpenAI setup. Model
ids come from the Varity catalog, not OpenAI's. See
[Models](/ai-gateway/models/) for the full list.

## Confirm The Gateway Before You Have A Key

`GET /v1/models` is public. Run it right now, with no credential, and you get a
`200` plus the live catalog:

```bash
curl https://ai.varity.app/v1/models
```

```json
  "privacy_scope": "anonymized",

```

The entry above is trimmed, and the rates are placeholders: `input`, `output`,
and `cached_input` are numbers in the real response. Read prices from
`GET /v1/models` or the **Models** tab on the portal's AI Gateway page, never
from this page.

The gateway also exposes unauthenticated health and readiness probes on the
canonical host; their response shapes are on
[Endpoints](/ai-gateway/endpoints/#health).

## Authentication

Inference requests require a Varity API key sent as a bearer credential:

```text
Authorization: Bearer $VARITY_API_KEY
```

Create keys on the Developer Portal's [AI Gateway page](https://developer.store.varity.so/dashboard/ai-gateway?utm_source=docs&utm_medium=content&utm_campaign=docs-to-portal&utm_content=ai-gateway-api-keys), under the
**Inference keys** tab, or with `POST /v1/keys` from a signed-in portal session.
Key plaintext is shown once
at creation and is never returned again; the list identifies each key by its
key id (`vki_…`). The same key format is used across the
Varity [public API](/ai-tools/api-reference/). A revoked key stops working
within 60 seconds. See [Billing and Keys](/ai-gateway/billing-and-keys/).

Inference is prepaid: add credits on the **Gateway billing** tab before your
first request. Each request is charged according to the live model catalog;
funding terms come from the live OpenAPI commercial-contract block.

Auth is enforced on every inference route. A request with no `Authorization`
header returns `401`:

```json
{
  "error": {
    "message": "A bearer credential is required.",
    "type": "authentication_error",
    "code": "authentication_required",
    "param": null,
    "retryable": false,
    "request_id": "516c24ef-ba5a-4e3d-8f32-0a609ae5d298"
  }
}
```

A malformed, revoked, or expired key also returns `401` with
`code: "authentication_required"`; only the message differs:
`The provided credential is invalid or expired.` Treat any `401` as "send a
valid key" rather than branching on the message text.

<Aside type="note">
Authentication is checked before the request body is validated. An unauthenticated
request naming a nonexistent model still returns the authentication error, not a
model error.
</Aside>

## Streaming

Set `stream: true` for server-sent events, exactly as with OpenAI. Read
`capabilities.streaming` per model rather than assuming it is universal.

<Tabs>
  <TabItem label="curl">

    ```bash
    curl https://ai.varity.app/v1/chat/completions \
      -H "Authorization: Bearer $VARITY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "glm-5-2",
        "stream": true,
        "messages": [
          { "role": "user", "content": "Count to five." }
        ]
      }'
    ```

  </TabItem>
  <TabItem label="Python">

    ```python
    stream = client.chat.completions.create(
        model="glm-5-2",
        messages=[{"role": "user", "content": "Count to five."}],
        stream=True,
    )

    for chunk in stream:
        delta = chunk.choices[0].delta.content
        if delta:
            print(delta, end="")
    ```

  </TabItem>
  <TabItem label="Node">

    ```javascript
    const stream = await client.chat.completions.create({
      model: "glm-5-2",
      messages: [{ role: "user", content: "Count to five." }],
      stream: true,
    });

    for await (const chunk of stream) {
      process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
    }
    ```

  </TabItem>
</Tabs>

Streaming *tool calls* are a narrower capability than streaming text, and are
only supported on some models. Check `capabilities.streaming_tool_calls` before
you combine `stream: true` with `tools`. See
[Compatibility](/ai-gateway/compatibility/).

## Errors

Errors use the OpenAI error envelope, with two Varity additions: `retryable` and
`request_id`. Quote `request_id` in any support request. The envelope, the
`x-request-id` header, and every error code are on
[Compatibility](/ai-gateway/compatibility/#errors).

## Rate Limits

Inference is bounded by a requests-per-minute budget and a concurrency bound,
both counted across your whole account. Crossing either returns `429` before any
model provider is called. The standard-tier numbers, how to read your own, the
headers each refusal returns, and the body-size ceilings are on
[AI Gateway Rate Limits](/ai-gateway/limits/).
