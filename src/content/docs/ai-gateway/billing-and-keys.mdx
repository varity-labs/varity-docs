The AI Gateway spends credits from your Varity balance, the same prepaid
balance Varity Cloud uses (**100 credits = $1**). Credits come from your plan,
from top-ups, or from the Free plan; see
[Billing and Pricing](/resources/billing/). An inference key is what your code
sends to spend them.

## How You Are Charged

- **API key requests** cost the provider cost of the request, including cache
  discounts, plus 5%. They need paid credits from a subscription or top-up;
  Free plan credits do not cover them.
- **Chat and Build** in the portal are charged from a versioned per-model
  credit rate card.
- **The Free plan** includes up to 50 credits of AI usage per day, on the
  cheapest suitable model. Any subscription or top-up removes the daily limit.
- You cannot bring your own provider key.

Per-model rates are in `customer_pricing` on
[`GET /v1/models`](/ai-gateway/models/#pricing) and on the **Models** tab of the
portal's AI Gateway page. This page lists no prices, because the catalog changes
without a docs release.

When a request cannot be paid for, it is refused with a `402` before any
model is called:

| Code | Meaning |
|------|---------|
| `insufficient_credits` | Your balance cannot cover the request. |
| `daily_free_limit_reached` | The Free plan's daily AI allowance is used up. |
| `subscription_required` | The request needs paid credits, for example an API key request on Free plan credits only. |
| `wallet_frozen` | Paid usage is paused on this account. |

The full list of billing codes is on [API Errors](/api/errors/#capacity-and-billing).
The older `insufficient_gateway_balance` code means the same as
`insufficient_credits` and is being retired; handle both.

## Adding Credits

Subscribe to a plan or buy a top-up on the billing page of the Developer
Portal. Top-ups have no fee, and top-up credits expire 12 months after
purchase. Optional auto top-up refills your balance when it falls below a
threshold you set, up to a monthly cap you choose.

## Inference Keys

Create, list, and revoke keys on the **Inference keys** tab.

- The key plaintext is shown **once**, when the key is created. Store it then;
  it is never returned again.
- Each key is identified by an id of the form `vki_…`.
- A key can be limited to a list of up to 64 model ids. An empty list allows
  every model, including models added later.
- A key has a privacy floor, `private` or `anonymized`. An `anonymized` key
  requires the account itself to allow anonymized processing first.
- A key can carry its own `requests_per_minute` and `concurrency_limit` (the
  smaller of the key's and the account's bound applies), a spending budget, and
  an expiry.
- **A revoked key stops working within 60 seconds.**

Send the key as a bearer credential on every inference request:

```text
Authorization: Bearer $VARITY_API_KEY
```

## Account Routes

The portal tabs are built on these routes on `https://ai.varity.app`. They take
a **Developer Portal session** as the bearer credential. An inference key is
refused on them with `403 portal_session_required`, so a leaked inference key
cannot mint more keys, move money, or change privacy settings. They are not in
`GET /v1/openapi.json`; this table is their public reference, and the only
place AI Gateway keys are issued is `POST /v1/keys` on this host.

| Route | What it does |
|-------|--------------|
| `POST /v1/keys` | Creates an inference key. Body: `name` (1 to 80 characters), `allowed_models` (array, may be empty), `privacy_floor`, and optionally `requests_per_minute`, `concurrency_limit`, `upstream_budget_usd`, `expires_at` (Unix seconds), `project_id`, `application_id`, `environment`. |
| `GET /v1/keys` | Lists the account's inference keys. No plaintext is ever returned. |
| `GET /v1/keys/audit` | Key lifecycle events. Accepts `limit` from 1 to 500. |
| `POST /v1/keys/{id}/revoke` | Revokes one of the account's own keys. |
| `GET /v1/billing/balance` | The balance: `availableBalanceUsd`, `reservedUsd`, `spendThisMonthUsd`, `monthlySpendingLimitUsd`, `autoReload`, and more. |
| `GET /v1/billing/transactions` | Balance transactions. Accepts `limit` from 1 to 100 (default 50) and `offset` from 0 to 10,000. |
| `PATCH /v1/billing/settings` | Sets `monthlySpendingLimitCents` (`null`, or 100 to 10,000,000) and `autoReload` `{ enabled, thresholdCents, amountCents }`. |
| `POST /v1/billing/top-up` | Starts a card checkout. Body: `email` (must belong to your account) and `balanceCents` (within the refill bounds of the live commercial contract; see [How You Are Charged](#how-you-are-charged)). Returns the checkout `url` plus `balanceCents`, `serviceFeeCents`, and `totalCents`. |
| `PUT /v1/inference/policy` | Sets the account privacy floor. See [Privacy Routing](/ai-gateway/compatibility/#privacy-routing). |

Under credit pricing, top-ups carry no fee, so `serviceFeeCents` is `0` and
`totalCents` equals `balanceCents`.

The request budgets for these routes are on
[Rate Limits](/ai-gateway/limits/#account-routes).

## Usage And Request History

Your own code can read what it has spent with an inference key, through the
`/v1/inference/*` routes listed on
[Endpoints](/ai-gateway/endpoints/#your-account-with-an-inference-key).

Request records hold metadata only, never prompt or response content, and are
kept for 30 days. See
[Privacy And Data Retention](/ai-gateway/compatibility/#privacy-and-data-retention).
