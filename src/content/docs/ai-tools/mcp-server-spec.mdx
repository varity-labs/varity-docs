The Varity MCP server (`@varity-labs/mcp`) runs locally over stdio and gives an
MCP-compatible editor access to Varity's published tools. The install command
uses npm's current `latest` release; an unreleased source branch is not evidence
of what that command installs.

<Aside type="note">
The machine-readable [`/mcp-schema.json`](/mcp-schema.json) is a conservative
documentation reference tied to the named npm release. It is not the MCP wire
contract. Your installed server's `tools/list` response is authoritative for
executable definitions. The scheduled check fails when npm's `latest` version
moves ahead of the reference's release marker.
</Aside>

## Prerequisites

- **Node.js 18 or newer**, as required by the package currently published to npm
- **Python 3.11 or newer** for the current `varitykit` CLI
- **varitykit**, installed with `pipx install varitykit`

## Setup

<Tabs>
  <TabItem label="Cursor">
    Add this to `.cursor/mcp.json` in your project:

    ```json
    {
      "mcpServers": {
        "varity": {
          "command": "npx",
          "args": ["-y", "@varity-labs/mcp"]
        }
      }
    }
    ```

    Restart Cursor after saving the file.
  </TabItem>
  <TabItem label="Claude Code">
    Run once:

    ```bash
    claude mcp add varity -- npx -y @varity-labs/mcp
    ```
  </TabItem>
  <TabItem label="VS Code">
    Add this to `.vscode/mcp.json`:

    ```json
    {
      "mcpServers": {
        "varity": {
          "command": "npx",
          "args": ["-y", "@varity-labs/mcp"]
        }
      }
    }
    ```
  </TabItem>
  <TabItem label="Windsurf">
    Add the same server entry to `~/.codeium/windsurf/mcp_config.json`.
  </TabItem>
</Tabs>

## Authentication

Use `varity_login` for interactive setup. For a headless process, provide
`VARITY_API_KEY` (or the package's compatibility name `VARITY_DEPLOY_KEY`) to
the MCP process. Never put a real key in a checked-in editor configuration.

The server can also read the credential written by varitykit. API keys are
account credentials; a project path is not an ownership boundary.

## Tool Reference

Use [`/mcp-schema.json`](/mcp-schema.json) for conservative usage guidance and
the release identity reviewed by Docs. Discover names, input schemas, and
annotations from the installed server before calling a tool. Do not copy a tool
table into automation from this page. The platform HTTP routes wrapped by
deployment tools are separately published at [`/openapi.yaml`](/openapi.yaml).

Important lifecycle semantics:

- A deploy, environment update, redeploy, or delete request can return before
  every runtime effect has converged. Track the returned state or operation.
- Deletion acceptance is not proof that routing, allocation release, and
  billing closure are all complete.
- A redeploy request reapplies saved configuration and can be a no-op. Do not
  describe it as a verified restart or image refresh without runtime evidence.
- Deployment-log availability depends on how the deployment was created. Use
  the local build tool for compilation diagnostics.
- Environment-variable values are write-only. Do not expect read APIs or tool
  results to echo secrets.

## Typical Workflow

1. Run `varity_doctor` to check local prerequisites.
2. Run `varity_login` if authentication is missing.
3. Use `varity_cost_calculator` or a live quote before a billable action.
4. Build locally and inspect the result.
5. Deploy the project or a certified template.
6. Follow the returned deployment state to a terminal outcome.
7. For deletion, verify terminal cleanup and billing state rather than treating
   request acceptance as closure.

The package also exposes local-development and repository helpers. Discover
their current schemas and annotations from the installed server's `tools/list`
response before calling them. Use `/mcp-schema.json` only for conservative Docs
guidance tied to its recorded release marker.

## Transports

The package supports:

- **stdio**, for local editor integrations; and
- **self-hosted HTTP**, for a server you operate yourself.

Start a local HTTP transport with:

```bash
npx -y @varity-labs/mcp --transport http --port 3100
```

It serves MCP at `http://localhost:3100/mcp`.

<Aside type="caution" title="No hosted MCP endpoint">
`mcp.varity.so` is retired. Varity does not currently operate a hosted MCP
transport. Browser-only clients that require a remote MCP URL cannot use the
local stdio package directly.
</Aside>

Local-browser and local-dev-server tools require local execution, so use stdio
for those workflows.

## LLM Context Without MCP

Clients that cannot run MCP can read:

- `https://docs.varity.so/llms-full.txt` for the generated documentation corpus.

These are documentation projections, not substitutes for live resource state,
quotes, or operation receipts.

## Troubleshooting

- If npm cannot resolve the package, confirm `node --version` meets the
  published package requirement and retry `npx -y @varity-labs/mcp`.
- If deploy tools cannot find varitykit, install it with pipx and run
  `varitykit doctor`.
- If an editor does not show the server, validate its JSON configuration,
  restart the editor, and inspect the editor's MCP process log.
- If a tool's behavior differs from this page, record the installed npm version
  first and use the matching package and platform contracts as evidence.
